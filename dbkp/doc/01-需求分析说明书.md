# 数据备份软件（dbkp / bk）需求分析说明书

> 对应实验报告模板"需求分析说明书（10 分）"章节。本文档中的每条需求都有
> 唯一编号（FR-xx），并在第 5 节"需求跟踪表"里映射到实现模块与测试用例，
> 做到"需求 → 代码 → 测试"三向可追溯。

## 1. 任务概述

### 1.1 引言
本软件是一个**纯 C++ 实现、零第三方依赖**的本地文件备份工具，命令行程序名为 `bk`。
它要解决的核心问题是：把一个目录树完整、可验证、可恢复地保存到一个自描述归档文件
（`.dbkp`）或一个镜像目录中，并在备份过程中提供压缩、加密、过滤与元数据保持能力。

阅读方式：第 2 节给出功能需求与用例（含正常流/备选流/异常流）；第 3 节是与外部
（用户、操作系统、文件）的接口约束；第 4 节是非功能指标；第 5 节是需求跟踪表。

### 1.2 综合描述
#### 1.2.1 产品的状况
全新自主产品，是《打包解包技术》《压缩解压及其关键技术》《加密解密》三次实验知识的
集成实现，不替代任何现有软件，也不依赖既有系统组件。

作用领域：单主机、可移动介质、本地网络盘上的**离线备份/归档**。
不作用领域：跨主机增量同步、云备份去重、多用户并发备份、备份介质的物理坏道管理。

#### 1.2.2 产品的功能（概览）
| 编号 | 功能 | 规格说明 |
|---|---|---|
| F1 | 归档备份/还原 | 目录树 → 单个 `.dbkp`；可反向完整还原 |
| F2 | 复制模式备份 | 目录 → 目录（逐文件复制 + CRC 校验），可反向还原 |
| F3 | 自定义压缩 | 自实现 Huffman、LZ77、LZ77+Huffman 级联、RLE、无压缩 |
| F4 | 自定义加密 | AES-256-CBC、ChaCha20、XOR（演示级）、口令派生 PBKDF2-HMAC-SHA256 |
| F5 | 完整性校验 | 记录级 CRC64 + 载荷 SHA-256 摘要 + HMAC 口令验证 + 篡改检测 |
| F6 | 元数据保持 | 类型/权限/属主/mtime·atime（含纳秒）/ctime/inode/设备号/硬链/符号链/设备文件 |
| F7 | 过滤选择 | 路径、名称、类型、时间、尺寸、属主 六个维度，AND 语义 |
| F8 | 定时备份 | `--every/--times/--keep`，时间戳命名 + 保留份数滚动删除 |
| F9 | 查看与比对 | `list` / `info` / `verify` / `compare` |
| F10 | 健壮性 | 密码错误、归档损坏、路径遍历攻击、超长路径、特殊文件降级 |

作用范围之外明确不做：网络传输、多播、GUI 图形界面、数据库存储、备份点级增量差异
（见第 6 节扩展预留）。

#### 1.2.3 用户类和特性
| 用户类 | 特征 | 关注点 |
|---|---|---|
| U1 运维/个人用户 | 只使用命令行，按周期备份资料 | 备份正确、能还原、能少占空间 |
| U2 审计/验收人员 | 需要证明备份可信 | `verify`/`compare`/`info` 输出与错误码 |
| U3 开发人员 | 集成或二次开发 | 稳定的归档格式、可单测的模块边界 |
| U4 攻击者（对抗性用户） | 提供恶意归档 | 必须被路径遍历、越界长度等防护拦下 |

### 1.3 运行环境
#### 1.3.1 基本配置
- 硬件平台：x86-64 PC，≥ 2 GB 内存（归档为流式读写，不整文件驻留内存）
- 操作系统：Windows 10/11（MinGW-w64 g++ 8.1）、Linux（g++ ≥ 7）、macOS（clang，POSIX 分支）
#### 1.3.2 其他配置
- 内存：峰值 ≈ 单个文件缓冲（1 MB）+ 目录项列表；48 MB 数据实测备份峰值 < 40 MB
- 硬盘：需要"源数据 × 1.1"的可用空间，备份前用 `freeSpaceAt()` 预检
- 文件系统：NTFS / ext4；支持硬链接、符号链接、FIFO/设备节点（后者仅 POSIX）
- 网络：不需要（完全离线）

## 2. 功能需求

### 2.1 功能划分
七个功能组：**备份执行**（归档/复制/定时）、**内容变换**（压缩/加密）、
**选择策略**（过滤/遍历）、**归档格式**（记录/块/校验）、**恢复**（还原/比对）、
**观测**（list/info/verify/selftest）、**平台适配**（Windows/POSIX 差异屏蔽）。

### 2.2 系统用例

#### UC-01 备份目录到归档
- **用例图**：`U1 --> (UC-01 备份目录到归档) --> (UC-11 压缩) --> (UC-12 加密) --> (UC-13 校验)`
- **简要描述**：用户指定源目录与 `.dbkp` 目标，程序遍历、过滤、变换后写出归档。
- **前置条件**：源目录存在且可读；目标可写；空间充足。
- **基本事件流**：
  1. 解析参数并打印生效的过滤器（`-v` 可见每项被过滤的原因）；
  2. 先序遍历目录树，根目录以 `.` 入档；
  3. 每个条目生成 512 字节记录（超长路径追加 `X` 扩展记录）；
  4. 文件内容按"压缩 → 加密"顺序变换后按 512 字节块对齐写入数据区；
  5. 计算记录级 CRC64、硬链接按 `(dev,ino)` 去重只存一份；
  6. 写尾部头块（载荷 SHA-256 + HMAC + 口令包装 + 目录索引）；
  7. 自动执行一次完整性自校验（`--no-verify` 可关闭）。
- **备选流**：目标是已存在的空目录 → 走复制模式（UC-02）；源含符号链接 → 存链接本身而非内容。
- **异常事件流**：见 2.3 错误响应表；密码错误、磁盘满、权限不足、非法参数均有专用错误码。
- **后置条件**：归档存在且 `verify` 通过；`info` 显示条目数与压缩率。

#### UC-02 从归档还原
基本事件流：读尾头 → 校验摘要/HMAC → 按记录先建目录与文件 → 数据解密解压 → 
最后**按先序的逆序**回填目录元数据（否则父目录时间会被后建的子项顶掉）。
异常流：目标非空且未加 `--force` → 拒绝并提示；口令错误 → `E_WRONG_PASSWORD`。

#### UC-03 复制模式备份（目录 → 目录）
逐文件复制 + 每次读写的 CRC64 复核，保留符号链接与权限；`restore <备份目录> <目标>`
可反向还原并自动比对差异数。实测 48 MB 数据 111 MB/s。

#### UC-04 定时备份与保留策略
`bk schedule <src> <dstDir> --every 10s --times 5 --keep 3`：每次生成带时间戳的独立归档
（`bk-YYYYmmdd-HHMMSS.dbkp`），完成后按 `--keep` 删除最老的若干份，保留的最新 N 份必须
仍可 `verify` 通过。

#### UC-05 选择备份内容（过滤，六维 AND）
路径（`--include/--exclude`）、名称（`--name/--no-name`）、类型（`--type`）、
时间（`--newer-than/--older-than`）、尺寸（`--min-size/--max-size`）、
属主（`--uid/--owner`）。**语义约定**（第 4 节 FR-07）：名称/尺寸/时间只决定"条目本身是否
入档"，不剪断目录下降；`--max-depth` 口径同 `find -maxdepth`（根下条目为第 1 层）。

#### UC-06 验证归档可信性
`verify` 自解压到临时目录并逐块比对 CRC64 与摘要；`compare <归档> <目录>` 做字节级树比对。
篡改任意一个字节必须被检出（用例：把偏移 600 处改为 0xFF → `rc=1`）。

## 3. 外部接口需求

### 3.1 用户界面（命令行）
无图形界面（按"纯 C++ 功能链优先"的取舍，GUI 会挤占核心功能时间且扣分风险高）。
界面为 `bk <子命令> [参数]`，`-h` 输出完整用法。约定：
- 成功：人类可读摘要（条目数、原始/存储字节、压缩率、CRC64）+ 退出码 0；
- 失败：`[ERROR]` 前缀日志 + 非 0 退出码（2 = 用法错误，1 = 运行失败，3 = 比对差异）；
- `-v` 输出 DEBUG（含每项被过滤的原因），`-q` 静默；两者为全局开关，可放在任意位置。

### 3.2 软件接口
- 不使用任何第三方库（Huffman/LZ77/RLE/AES-256/SHA-256/HMAC/PBKDF2/CRC64 全部自实现）。
- 依赖仅限：C++17 标准库、Win32 API（`FS_win.cpp`）或 POSIX（`FS_posix.cpp`）。
- 内部模块接口以 `include/` 下的头文件为唯一契约；错误码统一为 `DBKP::ErrCode`。

### 3.3 硬件接口
无专用设备。磁盘可用空间通过 `GetDiskFreeSpaceExW` / `statvfs` 查询。

### 3.4 接口（数据格式）要求——归档文件 `.dbkp`
| 区域 | 内容 |
|---|---|
| 记录区 | 每条 512 B：`recMagic(4)` `type(1)` `flags(1)` `pathLen(2)` `linkLen(2)` `mode(4)` `uid(4)` `gid(4)` `mtime(8+4)` `atime(8+4)` `ctime(8)` `ino(8)` `nlink(4)` `dev(4)` `major(4)` `minor(4)` `size(8)` `storedSize(8)` `crc64(8)` `compAlg(1)` `cryptoAlg(1)` `rsvd` 之后为内联 path(160) 与 link(96) |
| 扩展记录 | 路径/链接超出内联字段时，前置 `X` 记录分块承载（实测 444 字符相对路径可完整往返） |
| 数据区 | 压缩→加密后的字节流，按 512 B 块对齐 |
| 尾区 | 归档头：版本、算法 id、载荷 SHA-256、HMAC-SHA256、PBKDF2 盐与迭代次数、加密后的主密钥、目录索引、注释 |

## 6. 假设、依赖与扩展预留
- 假设：备份期间源文件不被并发修改（否则 CRC 复核会报差异，属预期行为）。
- 假设：口令由用户安全保管；程序不保存口令，丢失口令无法解密（设计上如此）。
- 扩展预留：记录里已有 `ino/dev/nlink/mtime/crc64`，增量/差异备份只需在 `Scheduler`
  里比较上一次归档的索引即可实现，接口已具备（见设计文档第 7 节）。


### 2.3 出错响应要求
| 场景 | 要求 |
|---|---|
| 口令错误/归档损坏 | `E_WRONG_PASSWORD`，非 0 退出码，不写出部分结果 |
| 归档被篡改 | CRC64/SHA-256/HMAC 任一失配即失败 |
| 记录含 `../` 逃逸路径 | `E_PATH_UNSAFE`，拒绝还原 |
| 长度字段越界/块非对齐 | `E_TRUNCATED_ARCHIVE` / `E_INVALID_DATA_RECORD` |
| 源不可读/不存在 | `E_SOURCE_NOT_FOUND` / `E_PERMISSION_DENIED`，复制模式降级为警告并继续 |
| 特殊文件（FIFO/设备/套接字） | 记录元数据但降级为占位，警告而非崩溃 |
| 路径超过 260 字符 | Windows 内部自动加 `\\?\` 前缀，必须能备份与还原 |
| 命令行含中文目录名 | 通过 Unicode 命令行取参，UTF-8 内部统一，不得乱码 |
