# 数据备份软件（dbkp / bk）测试报告

> 对应实验报告模板"软件测试报告（20 分）"。所有数据均为撰写当天在
> Windows 11 + MinGW g++ 8.1 上**实测**产生，可用 `script/_verify.ps1`、
> `script/e2e.ps1`、`script/perf.ps1` 复现。

## 1. 引言
- **目的**：验证功能与需求说明书（FR/NF 编号）一致；验证正确性、完整性、安全性、健壮性与性能。
- **范围**：单元层（模块函数）+ 端到端层（真实进程命令行往返）+ Web 端到端层（真起 `bkd` 进程走 HTTP/SSE）+ 性能与对抗性用例。
- **环境**：Windows 11 / x86-64 / NTFS；g++ 8.1.0 `-O2 -g`；被测程序 `bin/bk.exe`。
- **工具**：自带迷你 GoogleTest 框架（与 gtest 宏兼容，`make gtest` 可切换真实 gtest）、
  PowerShell e2e 脚本、Python 独立参考实现（校验 SHA-256/PBKDF2/AES 官方向量）。
- **通过判定**：单元测试退出码 0；e2e `TOTAL FAIL=0`；性能与健壮性用例逐条对照预期。

### 2.3 Web 服务端端到端冒烟（48 项，全部通过）
`powershell -File script/smoke_web.ps1` → `WEB SMOKE OK`，退出码 0。

Web 层没法只靠单测覆盖（要真进程、真 socket），所以配了一个自包含冒烟脚本：
在临时沙箱造 3 个文件（含一个中文文件名）→ 起 `bin/bkd.exe --data-root 沙箱 --password …`
→ 用 `Invoke-WebRequest` 走完整业务链路 → `POST /api/shutdown` 收尾并确认进程自己退出。
断言一律按**接口契约**而不是时序写：快任务抢在取消指令之前跑完也算通过，只要求终态合法。

| 段落 | 断言（节选） | 实测 |
|---|---|---|
| 静态页与服务信息 | `GET /` 返回首页；`/api/info` 免鉴权且不泄露口令；未登录访问 `/api/config` → 401 | 48/48 ✓ |
| 登录鉴权 | 错口令 401；正确口令返回 token；带 `Authorization: Bearer <token>` 放行；算法列表含 huffman | ✓ |
| 建备份任务 | `POST /api/jobs` → 201；`mode=archive` 自动判定；轮询到 `succeeded`；`entriesDone>=3`；`?log=1` 取到任务日志；归档文件落盘 | ✓ |
| 读归档卷标 | `/api/stat?path=<Percent 编码的中文路径>` → 200，`algorithm=huffman`、条目数 ≥3 | ✓ |
| 还原 + 校验 | 还原任务 `succeeded`；中文文件名与普通文件都还原到位；`verify` 归档通过 | ✓ |
| 取消与错误处理 | 取消返回 200（或已抢先跑完 409）；终态 ∈ {succeeded, canceled}；"声称取消成功却不是 canceled"判失败；对已结束任务再取消 → 409；来源不存在 → 400；空请求体 → 400；未知接口 → JSON 404；不支持方法 → 405 | ✓ |
| 越界防护 | `dataRoot` 之外的 source → 400；`browse?path=../../../Windows` → 403；`GET /%2e%2e/Makefile` → 403；`source=../outside` → 400 且 `msg` 里给出解析后的绝对路径 | ✓ |
| 相对路径基准 | `browse?path=.` 列出 dataRoot 本身；`browse?path=src` 命中 `dataRoot/src`（含 `a.txt`）；`POST /api/jobs {source:"src",destination:"out/rel.dbkp"}` → 201，回显绝对路径落在 dataRoot 内 —— 证明相对路径按 `--data-root` 而不是进程工作目录解析；`/api/config` 的 `dataRoot` 已是绝对路径（相对形式的 `--data-root` 在启动时被归一）；`browse?path=../outside` → 403 且 `msg` 里带上这个绝对根 | ✓ |
| 浏览弹窗契约 | `browse` 条目里必须有被标记为目录的项（`isDir` / `dir` / `type=='D'` 任一）——前端认不出目录就会把文件夹当文件，点不进下一层；到根时 `data.parent` 必须是**存在的空串属性**（用 `PSObject.Properties` 判，否则"字段缺失"和"值为空串"在 PowerShell 里都是 `$null`，断言会空过）；`path=src` 的 `parent` 回指 dataRoot | ✓ |
| SSE 进度流 | `Content-Type: text/event-stream`；`event: hello` 开始、`event: done` 收尾；事件 JSON 内含 `state` | ✓ |
| 列表与关服 | `GET /api/jobs?limit=10` 返回 ≥4 条且按新→旧；`POST /api/shutdown` → 200 且 bkd 进程随后退出 | ✓ |

原始输出留在 `tmp/smoke_out.txt`，服务端 stderr 收进 `tmp/bkd-smoke.log`：
整轮只有 6 条 WARN，且全部是负向用例故意触发的（错口令登录、用户取消、越界来源两次——
绝对路径与相对路径各一次、空请求体）——
即"服务端没有非预期的错误日志"这一条也一并纳入验收。

前端那一侧有两个互补的自检。`node script/check_webui.js`（**不需要浏览器也不需要服务在跑**，
44 项断言）取出 `web/index.html` 的 `<script>` 段，套一层最小 DOM/fetch 桩执行一遍——页面脚本
有语法错或引用错会当场失败——再对目录浏览用到的路径 helper 断言边界：反斜杠归一、结尾斜杠、
盘根 `D:/` 与其父级、`.` 的父级、`joinOf('.', "src")` 不产生 `./src`、输入框里是文件名时浏览
起点退到它所在目录（`browseSeed`）、`withinRoot()` 不被 `/srv/data` 与 `/srv/database` 这种前缀
糊弄、HTML 转义；再把 JS 里 40 个 `$('id')` 引用与页面 40 个 `id` 声明逐一对账，最后**拿前端读的
字段名去 `src/Web/Api.cpp` 的 `hBrowse` 段里逐个对**（`name/type/isDir/dir/size/mtime/path/parent/
dataRoot/total/truncated/entries`），单方面改字段名直接红。

`node script/check_webui_live.js [URL]` 则是对着**正在跑的 `bkd`** 复现交互链路：手搓的最小 DOM
带 `children`/`classList`/`onclick`，所以它会真的去点列表行，验证"点一下确实换了目录""到根时
`上一级` 被隐藏""连点越界不会把游标丢到根外"。

本轮 browse 上线后用户报"点了不跳转、卡在一个页面"，用后者复现出两处契约失配：服务端条目字段
叫 `isDir` 而前端读 `dir`，于是**所有文件夹被渲染成“文件”**，点击只会选中、永远进不去下一层；
服务端又没给 `parent`，“上一级”按钮到根也不隐藏，点一次游标就落到根外，之后每次点击都是 403，
弹窗彻底翻不动。修法是服务端补 `dir` 别名与 `parent`/`dataRoot`，前端三种目录标记都认、缺
`parent` 时本地退一级、越界由 `withinRoot()` 先挡并在到根时隐藏按钮；回归由上面两个脚本加
`smoke_web.ps1` 新增的 3 条断言（45→48）共同守住。

它不替代 `smoke_web.ps1`：后者管接口契约，前两者保证页面自身与字段名不出低级错。

browse 修好能进目录后，用户又报"一打开页面就是弹窗、点取消也关不掉"，这是第三类坑：**CSS 声明
顺序**。`.hide { display:none }` 写在第 46 行，第 48 行的 `.mask { … display:flex }` 与它**特异性
相同（都是单个 class）**却声明在后，于是赢——`class="mask hide"` 的遮罩从加载起就铺满屏幕，JS
里 `classList.add('hide')` 全部无效。这类错 DOM 桩和冒烟脚本都看不见（它们不算样式），只能静态
比：现在 `check_webui.js` 会抽出 `<style>`（先剥掉注释，否则注释里的示例代码会干扰定位）、找出
所有与 `hide` 并存的组件类（HTML 写死的 + JS `toggle('hide')` 那个元素的 class），再检查有没有
`display:` 非 none 的规则声明在 `.hide` 之后——有就必须靠 `!important` 赢。修法即把 utility 写成
`.hide { display:none !important; }`；把 `!important` 删掉重跑，该断言报
`被声明顺序打败: .mask{mask}` 并 exit=1，证明它真会咬。

| 7 | Web 冒烟 | `bearerToken()` 按 6 个字符切前缀，而 `"Bearer "` 是 7 个（含空格）→ token 前多一个空格，签名校验必然失败，表现是"登录后仍然 401" | 改为 `substr(0,7)` 比较；顺带保留 `?token=` 回退（EventSource 不能设头） | `WebHttp.BearerTokenParsing` + 冒烟鉴权段 ✓ |
| 8 | Web 冒烟 | `parseHttpRequest()` 忘了调用 `setRawTarget()`，`m_rawTarget` 恒空 → **全部 `?k=v` 查询参数静默失效**：`/api/stat` 的 path、`/api/events` 的 job、`/api/jobs` 的 log 统统落回默认值，症状是"403 / SSE 不收尾 / 任务日志空"，极易误判成三个独立 bug | 解析时保存原始 target；单测直接锁死这一条 | `WebHttp.QueryStringIsKept` + 冒烟三处转绿 ✓ |
| 9 | Web 冒烟 | `bkd` 的 `--data-root` 经 Windows **ANSI argv**（GBK 字节串）传入，而 HTTP 请求体里的路径是 UTF-8 → 沙箱比对永远不通过，所有任务被误判"超出允许访问的根目录"。CLI 侧早有修复，但那段代码写在 `main.cpp` 里没复用 | 把 `CommandLineToArgvW` + `SetConsoleOutputCP(CP_UTF8)` 抽成 `Platform/Args.h`，`bk` 与 `bkd` 共用 | 正常任务受理、越界用例只拒"真越界" ✓ |
| 10 | Web 冒烟 | 两类"响应发不出去"：① handler 里直接 `server->stop()`，把当前连接一起 shutdown，`/api/shutdown` 的响应永远到不了客户端；② 写完响应立刻 `closesocket()`，若本端还有未被 ACK 的数据就发 RST，把响应体销毁（PowerShell 侧只见响应头、body 为空）；③ 另外 .NET 客户端 POST 默认带 `Expect: 100-continue`，不回 100 它会干等超时 | ① 只置 `stopRequested` 标志，由主循环在响应之后停服；② 收尾改为 `drain → shutdown(FIN) → close`；③ 请求体未收齐且带 Expect 时先回 `HTTP/1.1 100 Continue` | 冒烟 `POST /api/shutdown` 返回 200 ✓；.NET 客户端建任务成功 ✓ |
| 11 | Makefile 审查 | `$(shell uname -s 2>/dev/null)` 在 Windows 由 cmd 执行：找不到 `uname` 之外，`/dev/null` 还会让**每次构建**都打印"系统找不到指定的路径"，看着像构建失败 | 把该探测移入非 Windows 分支，Windows 下不再调 `$(shell)` | `mingw32-make dirs` 静默 ✓ |

## 7. 结果分析与遗留风险
- **通过率**：单元 102/102，命令行端到端 19/19，Web 端到端冒烟 39/39，性能与健壮性用例全部符合预期。
