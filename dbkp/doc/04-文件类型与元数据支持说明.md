## 一、功能实现总览

### 1.1 支持的文件类型（9 种）

类型枚举定义在 [include/Common/Defs.h:65-73](../include/Common/Defs.h)，英文描述表在 [src/Common/Defs.cpp:42-50](../src/Common/Defs.cpp)：

| 字符 | 枚举 | 中文 | 英文（`fileTypeToDesc`） | POSIX 判定 | Windows 判定 |
|---|---|---|---|---|---|
| `-` | `FT_REGULAR` | 普通文件 | regular file | `S_ISREG` | 默认 |
| `D` | `FT_DIR` | 目录 | directory | `S_ISDIR` | `FILE_ATTRIBUTE_DIRECTORY` |
| `L` | `FT_SYMLINK` | 符号链接 | symbolic link | `S_ISLNK` | `IO_REPARSE_TAG_SYMLINK` + **`IO_REPARSE_TAG_MOUNT_POINT`（junction）** |
| `B` | `FT_BLOCK` | 块设备 | block device | `S_ISBLK` | 不适用 |
| `C` | `FT_CHAR` | 字符设备 | character device | `S_ISCHR` | 不适用 |
| `F` | `FT_FIFO` | 命名管道 | named pipe (FIFO) | `S_ISFIFO` | 不适用 |
| `S` | `FT_SOCKET` | Unix 套接字 | unix socket | `S_ISSOCK` | 不适用 |
| `H` | `FT_HARDLINK` | 硬链接（同 inode 后续项） | hard link | `st_nlink > 1` 去重 | 同 |
| `X` | `FT_EXTEND` | 扩展记录（超长 path/link） | extended header | — | — |

关键实现位置：

- POSIX 类型判定：[src/Platform/FS_posix.cpp:49-56](../src/Platform/FS_posix.cpp) `typeFromMode()`，用 `lstat`（不跟随链接）取真实类型（`:83`）。
- Windows 类型判定：[src/Platform/FS_win.cpp:52-94](../src/Platform/FS_win.cpp) `typeFromAttrs()`。**批次 2 的 F1 修复**把 `IO_REPARSE_TAG_MOUNT_POINT`（junction）也归入 `FT_SYMLINK`，此前 junction 被误判成目录（见 `FS_win.cpp:66-70` 注释与 [test/test_regress_f1.cpp:119](../test/test_regress_f1.cpp) `junction_classified_as_symlink`）。
- 链接目标读取：`FS_posix.cpp:readLink()`（`::readlink`）、`FS_win.cpp:161`（解析 reparse data buffer，统一处理 symlink 与 mount point 尾部布局）。
- 硬链接去重：打包时同 inode 的后续项只记 `FT_HARDLINK` + 首次出现路径，不重复存数据（`Defs.h:72` 注释）。

### 1.2 特殊文件的处理策略（这是"支持"的完整含义）

不是"能识别就算"，而是**识别 → 存档 → 还原 → 校验**四段都有明确行为：

| 阶段 | 位置 | 行为 |
|---|---|---|
| 识别 | `FS_posix.cpp:83` / `FS_win.cpp:94` | `lstat` 取真实类型，链接目标入 `FileInfo::linkTarget` |
| 存档 | [src/Pack/MyPack.cpp](../src/Pack/MyPack.cpp) 记录构造段 | `type`/`link`/`mode`/`uid`/`gid`/`major`/`minor`/`nlink` 全部写入 512B 记录 |
| 可选跳过 | [src/Enumerator/FilterOptions.cpp:74-75](../src/Enumerator/FilterOptions.cpp) | `--skip-special` / `skipSpecials`：FIFO/块设备/字符设备/套接字不入档 |
| 还原 | [src/Pack/MyPack.cpp:636-650](../src/Pack/MyPack.cpp) | `makeFifo(rec.mode)` / `makeDeviceNode(type, major, minor, mode)` / socket 建占位并 WARN |
| 还原失败降级 | 同上 `:638`、`:643-645` | 平台不支持 → `E_UNSUPPORTED_FEATURE` WARN 跳过；非 root 建设备 → `E_PERMISSION_DENIED` WARN；**不中断整卷还原** |
| 校验 | `MyPack.cpp` verify 分支 + [src/Backup/BackupEngine.cpp](../src/Backup/BackupEngine.cpp) | `symlink target differs` 单独报差异；特殊文件计入 `specialCount`（`MyPack.cpp:1023`） |
| 安全围栏 | `FS_win.cpp` + [src/Utils/PathUtil.cpp](../src/Utils/PathUtil.cpp) | 还原前 `canonicalPath` 展开 junction/symlink 链，拒绝逃逸出根的链接（F1，`test_regress_f1.cpp:216`） |

**socket 明确说明不能忠实还原**（`MyPack.cpp:648`），这是诚实的降级而非隐瞒。

### 1.4 元数据的还原（写回磁盘）

[src/Pack/MyPack.cpp:654-672](../src/Pack/MyPack.cpp) `applyMetadata()`，三段独立、按标志位生效、失败只降级不报错：

```cpp
if (rec.flags & RF_META_TIME) Platform::setTimes(absPath, mtimeSec, mtimeNSec, atimeSec, atimeNSec, followSymlink);
if (rec.flags & RF_META_MODE) Platform::setMode(absPath, rec.mode);
if (rec.flags & RF_META_UID)  Platform::setOwner(absPath, rec.uid, rec.gid);
```

- 时间：POSIX 走 `utimensat`（`AT_SYMLINK_NOFOLLOW`，不跟随链接改时间），Windows 走 `SetFileTime`，支持 100ns 精度。
- 属主：POSIX `lchown`（`FS_posix.cpp:setOwner`）；Windows 明确 `supportsOwner() == false`（`FS_win.cpp:454`），**不假装成功**。
- 用户名互转：`uidToName` / `nameToUid`（POSIX 用 `getpwuid`；Windows 返回 `E_UNSUPPORTED_FEATURE`，见 `FS_win.cpp:458-459`）。
- CLI 开关：`--preserve-meta` / Web `preserveMeta`（[web/index.html:178](../web/index.html)）。

页面 `web/index.html`（888 行 / 非空 843 行，`git blame` 显示由 `yang-pppeiwen` 独立编写）实测统计，后端已经返回的字段在前端出现次数为 **0**：

```
e.mtime          前端出现次数 = 0
```

三处缺口：

### 缺口 1：能力条漏掉 3 项（`index.html:309-311`）

```js
$('cap').textContent = info.capabilities
  ? ('软链 ' + yn(info.capabilities.symlink) + ' · 硬链 ' + yn(info.capabilities.hardlink)
     + ' · 属主 ' + yn(info.capabilities.owner)) : '';
```

`fifo`、`deviceNode`、`nanoTime` 后端已返回，页面不显示。**这三项恰好是"特殊文件支持"和"元数据精度"最直接的自证。**

### 缺口 2：条目表只有 6 列（`index.html:623-642` `renderEntries`）

现有列：`路径 / 类 / 原始 / 存成 / 算法 / CRC64`。
后端 [Api.cpp:767-780](../src/Web/Api.cpp) 每行实际返回 13 个字段，其中 **`mode`、`uid`、`gid`、`mtime`、`mtimeNs`、`nlink`、`crypto` 七个被直接丢弃**。

讽刺的是函数注释写着"元数据一直在归档里，这里把它摊开"（`index.html:622`），实际只摊开了尺寸与校验。

### 缺口 3：类型列显示裸字符，特殊文件无法辨认（`index.html:634`）

```js
'<td>' + escapeHtml(e.type) + '</td>'
```

API 返回的是单字符 `'-' 'D' 'L' 'B' 'C' 'F' 'S' 'H'`（`Api.cpp:768` 用 `std::string(1, r.type)`），页面原样打印。用户看到 `F` 不知道那是命名管道，看到 `B` 不知道是块设备。后端 `fileTypeToDesc()` 的中文名/英文名现成可用，前端没用。

另外 `stat` 摘要（`index.html:608-617`）显示了条目数/目录数/链接数，但**没有 `specialCount`**（`Api.cpp:748` 已返回）。

### 附带说明：CLI 侧其实是完整的

`bk list --long` 打印 `T ALG MODE UID GID MTIME ATIME SIZE NLK CRC64 PATH`（[src/main.cpp](../src/main.cpp) 的 `--long` 分支，注释原文："以前 mode/uid/gid/纳秒时间/ino/nlink 备得进去…"）。

## 五、答辩可直接使用的表述

> **文件类型支持**：归档用单字节 `type` 字段表达 9 种类型（普通/目录/符号链接/块设备/字符设备/命名管道/Unix 套接字/硬链接/扩展记录）。POSIX 侧由 `lstat` 的 `st_mode` 位判定；Windows 侧解析 reparse point，并额外把 junction（`IO_REPARSE_TAG_MOUNT_POINT`）与符号链接同类处理——这是批次 2 修掉的一个真实缺陷。特殊文件不止"能认"，还原时分别调 `mkfifo` / `mknod`（带主/次设备号），平台不支持或缺权限时降级为 WARN 并跳过，绝不中断整卷还原；套接字明确声明无法忠实还原，只建占位。还原前还会展开 junction/符号链接链做规范化路径校验，拒绝逃逸出备份根的链接。

> **元数据支持**：每条记录固定 512 字节，逐字段小端序列化，不依赖 `sizeof`、padding 或本机字节序，因此跨平台可移植。存 mode（`& 07777`）、uid/gid、mtime/atime 的秒 + **纳秒**、ctime、inode 号、硬链接计数 `nlink`、设备号 `dev`、设备节点主/次号码 `major`/`minor`。用 `RF_META_MODE/UID/TIME` 三个位标记记录"这一项是否真的有效"——Windows 上 `supportsOwner()` 返回 false，就**不置位、也不谎称恢复成功**。还原时 `applyMetadata()` 按位分别调 `utimensat`（带 `AT_SYMLINK_NOFOLLOW`，改链接本身而非目标）/ `chmod` / `lchown`，失败只降级。`bk list --long` 可把这些字段全部打印出来。

> **诚实的边界**：Windows 没有 POSIX 意义的属主与设备节点，`/api/info` 的 `capabilities` 如实报 `owner:false`、`fifo:false`、`deviceNode:false`，程序按能力位降级运行，不做假动作。
