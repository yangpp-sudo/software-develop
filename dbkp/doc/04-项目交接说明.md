## 1. 项目是什么

纯 C++17、零第三方依赖的本地文件备份工具，同一套内核提供两个入口：

| 入口 | 程序 | 说明 |
|---|---|---|
| 命令行 | `bin/bk.exe` | 备份/还原/校验/对比/列表/定时/实时，7+ 子命令 |
| Web 服务 | `bin/bkd.exe` | HTTP + JSON + SSE，浏览器打开即用的单页控制台（`web/index.html`） |

核心能力：`.dbkp` 单文件归档 与 目录逐文件复制 双模式；自实现压缩（huffman/lz77/lzhuff/rle）、加密（AES-256-CBC/ChaCha20/DES-EDE/XOR 教学）、哈希（CRC64/SHA-256/HMAC）；POSIX 元数据保持；六维过滤；定时备份；实时备份；跨平台（Windows/POSIX）。

## 3. 构建与运行

### 3.1 构建（Windows 本机）

```powershell
cd dbkp
mingw32-make -j4 all bin/bk_test.exe
```

- 工具链：MinGW-w64 g++（本机 14.1.0），用 `mingw32-make`。
- 产物：`bin/bk.exe` / `bin/bkd.exe` / `bin/bk_test.exe`，对象文件在 `obj/`。
- 注意：**不要混用不同来源的 MinGW 产物**（曾出现过混合编译器版本导致运行时死锁），要么全量重建。
- 只改 `web/index.html` 不需要重编：`bkd` 每个请求从磁盘现读 web 目录，Ctrl+F5 即生效。

### 3.2 启动 Web 控制台（本机实跑命令）

```powershell
cd dbkp
.\bin\bkd.exe --port 8099 --web web --data-root .
```

浏览器打开 `http://127.0.0.1:8099/`。本机当前即以此方式运行（数据根 = `dbkp/`，路径含中文"软件开发实验"，已实测可用）。

常用参数：`--host`（默认 127.0.0.1）、`--password` / `--password-sha256`、`--token-ttl`、`--secret`、`--workers`（1~8）、`--max-body`、`--no-static`、`--config`、`--log-level`。
相对路径一律按 `--data-root` 解析（不是按启动目录）；越界返回 403。

### 3.3 CLI 子命令

```
bk backup   <src-dir> <archive.dbkp|dst-dir> [options]
bk restore  <archive.dbkp|backup-dir> <dst-dir> [-p pass] [--force] [--no-meta]
bk watch    <src-dir> <archive-dir> [--debounce 2s] [--keep N] [--prefix P]
bk schedule <src-dir> <archive-dir> --every 10s --times 5 --keep 3
bk list|info|verify <archive.dbkp> [-p pass]
bk compare  <archive.dbkp> <src-dir> [-p pass]
bk selftest            # 算法 known-answer 自检
pack/unpack 是 backup/restore 的别名
```

## 5. Web API 一览（响应统一 `{code,msg,data}`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/info` | 版本、能力（symlink/hardlink/owner/fifo/deviceNode/nanoTime/os），免鉴权 |
| POST | `/api/login` | 口令换 token（无口令时 anonymous=true），有失败退避锁定 |
| GET | `/api/config` | dataRoot、defaultAlgorithm、algorithms/cryptos/checksums/modes |
| GET | `/api/browse?path=` | 目录浏览（限数据根内，最多 1000 项） |
| GET | `/api/stat?path=&entries=1` | 归档卷标 + 条目（path/type/mode/uid/gid/mtime/mtimeNs/nlink/algorithm/crypto/crc64/link） |
| GET | `/api/compare?archive=&origin=&password=` | 归档 vs 源目录逐条比对（同步） |
| POST/GET | `/api/jobs` | 建任务（201 返回 `data.mode`）/ 列表（**列表项不含 mode**） |
| GET | `/api/jobs/:id?log=1` | 单任务详情/日志 |
| POST | `/api/jobs/:id/cancel` | 取消 |
| POST/GET/POST | `/api/watch` `/api/watch/stop` | 实时备份 启动/状态/停止 |
| POST/GET/POST | `/api/schedule` `/api/schedule/stop` | 定时备份 启动/状态/停止 |
| GET | `/api/events?token=&job=` | SSE：hello/tick/done/ping |
| POST | `/api/shutdown` | 优雅停机（仅回环） |

任务类型：`backup / restore / verify / compare`。`mode=auto` 只按目标后缀判定（`.dbkp`→archive，否则→copy）；显式 `archive/copy` 强制。`copy` 模式压缩/加密/校验和/密码全部不生效。

## 8. 已知限制与坑（如实交接）

1. **权限列**：Windows 下后端返回 mode=0644/0755 等模拟值，前端显示真实八进制（不是 —）。属主列显示 —。答辩材料若要求"Windows 全部显示 —"，按 `capabilities.os` 判断改一行即可。
2. **符号链接**：Windows 创建符号链接需管理员权限；测试用 Junction 代替（后端识别为 `L` 符号链接）。
3. **copy + `.dbkp` 目标**：后端不拦（真会建出一个叫 `oops.dbkp` 的目录），只有前端 `currentFails()` 拦。若要补，应在 `Api.cpp` 的 `Spec::parse` 加校验。
4. **任务卡 mode 标签**：`GET /api/jobs` 响应没有 mode 字段，标签来自提交响应 + sessionStorage；刷新页面后旧任务无标签。根治需 `JobManager::toJson` 增加 mode。
5. **auto 只看后缀**，显式 archive/copy 强制；copy 模式不打包，压缩/加密/校验/密码全部不生效。
6. **引擎不代建归档父目录**：目标父目录需提前存在（Web 页面提交前最好先建目录）。
7. **PowerShell 5.1 三坑**：中文 Body（Latin-1）、无 BOM 脚本（ANSI）、`.NET` 相对路径（按进程 CurrentDirectory）。写脚本一律 UTF-8 + BOM + 绝对路径。
8. **实时备份是"变化即全量重打"**，没有增量（增量是预留扩展）。
9. **bkd 定位本机/局域网单人**：每连接一线程、无 keep-alive/chunked、无 TLS；`--host 0.0.0.0` 务必配口令。
10. **README 数字过期**（102 项测试、8080、15 个测试文件），以本文为准。
